> 注: 本文中の `test/...` のパスと数値は、移植元(ベースライン)である現行 `test/` を指す。`re_test/` で作業する際は、同名ファイルを `re_test/` 側で探すこと(未移植のものは `test/` を参照)。

> 対象: `cycle_map/test/`(`application/` の実験フォーク)。`plans.md`(同ディレクトリ)を実行するAIエージェント向け。
> 範囲: 主にロジックとUI。ビルド環境やデータパイプラインは `AGENTS.md` を参照。
> 数値は 2026-10-12 時点の `grep` による実測(`test/app/src/main/java`)。変更後は古くなるので、鵜呑みにせず再確認すること。

## 0. 最優先の3原則

1. **挙動を変えない移動と、挙動を変える修正を同じコミット/作業に混ぜない。** `MapScreen.kt`(4,133行)等の分割時は、移動のみ行い、前後で実機スクリーンショットとユニットテストが一致することを確認する。
2. **UIで直したものは、テストで固定する。** 過去に直した不具合(ルート線の隠れ、バナー被り、ダーク/ライト不一致)は、UI層にテストがなく再発しやすい。
3. **オフラインを正とする。** オンライン時の挙動は上乗せにとどめ、機内モードで動かない機能は不合格とする(詳細は `plans.md` §2)。

## 1. アーキテクチャ上の注意

### 1.1 地図エンジンが二重に存在する
- `osmdroid`(ラスター)と `MapLibre`(3Dベクター)が併存している(参照 約100箇所)。
- **危険**: 片方だけ直して他方を放置すると、レイヤー切替で挙動が食い違う(ズーム・回転・タップ座標・マーカー・ルート線)。
- 対策: 座標変換・タップ処理・マーカー描画は**共通インターフェース**(例: `MapEngine`)の背後に置く。新機能は MapLibre 側を主とし、osmdroid 側は「表示できること」だけを保証する。どちらを正とするかを `plans.md` の作業前に確認すること。

### 1.2 巨大ファイル
| ファイル | 行数 | 注意 |
|---|---|---|
| `MapScreen.kt` | 4,133 | 状態が 127 個の `mutableStateOf`/`remember` に散在。再コンポーズの原因を特定しにくい |
| `CyclingPanels.kt` | 2,232 | パネル間で状態を共有しがち |
| `SearchHelper.kt` | 1,355 | クエリ正規化・ランキング・DBアクセスが混在 |
| `VectorMapView.kt` | 1,001 | レイヤー追加順がハードコード |

- 機能追加は**新規ファイルへ**。既存巨大ファイルへ「ついでに」追記しない。
- 状態は `ViewModel` + `StateFlow` に引き上げ、Composable は状態を受け取って描画するだけにする。

### 1.3 `application/` との二重管理
- `test/` は `application/` の複製から派生している。`test/` にあるファイル(`VectorMapView.kt`、`GoogleNav*`、`DayNightManager`、`power/*` など)は本体に無い。
- 共通部分(`routing-core`、`osm-importer`)を `test/` だけで変えると**本体と差が開く**。修正が共通ロジック(特に `routing-core`)に及ぶ場合は、`diff -r application/routing-core test/routing-core` で差分を把握し、報告に「本体へ戻すべき変更」として記す。
- バイナリ形式(`.graph` / `.graph.idx`)を変更する場合は**バージョン番号を上げ**、旧版を読んだら明示エラー+再生成案内を出す。黙って誤読させない。

## 2. ロジックの注意点

### 2.1 ルーティング
- **A\* の最適性**: `CyclingCostModel` の最小倍率 0.90 はヒューリスティックの下限。コスト係数を **0.90 未満にすると最適性が崩れる**。新モード(徒歩・車)を足す場合は、モードごとにヒューリスティックの下限を再計算する。JVM 側と `LazyMappedRoadGraph` の両方に同じ値を反映する(同期漏れが過去にバグ化: BUG-75)。
- **ペナルティはエッジ単位で足す**。累積コスト全体に掛けない(BUG-75 の再発パターン)。
- **2GB 超オーバーフロー**: `LazyMappedRouting.readEdge()` の `offset.toInt()` は 2GB 超で破綻する既知の制約。大きな県(広島196MBは安全)以外や全国グラフを扱う前に `Long` 化する。
- `nearestNodeIndex` は O(n) の線形走査。長距離ナビ中に毎秒呼ばない(リルート判定は直近の探索結果から局所探索にする)。空グラフ(ノード0)で例外を出さない(BUG-83)。
- **複数ルート**(ペナルティ法)は、類似判定が甘いと「ほぼ同じ3本」になる。重なり率の閾値をテストで固定する。
- **リルート**: 再探索中に旧ルートを消さない。消すと一瞬ルート線が無くなるチラつきが出る。再探索結果が古い位置基準になる競合(結果が返った時にはさらに進んでいる)を、**結果適用時に現在位置から再スナップ**して吸収する。

### 2.2 位置・センサー
- 方位センサーの **NaN を必ず弾く**(BUG-79: 平滑化方位が永久に壊れる)。角度の平滑化は**円周上**で行う(359°と1°の平均は0°)。
- 距離計算は `haversine` の `a` を `[0,1]` にクランプ(BUG-82)。距離関数を新規に書かず、既存の `MapUtilities` を再利用する。
- GPS が弱い/トンネルでは Dead Reckoning(`DeadReckoner`)へ移行し、**復帰時に急ジャンプしない**ようスナップを補間する。
- 追跡は `LocationTrackingService` が前景サービスで動く。**Activity が破棄されても記録が続く**ため、状態の二重管理(Service と UI で別の距離/時間)を作らない。単一の情報源を Service 側に置く。
- バッテリー: `CameraMotionPolicy` / `BatteryMonitor` の方針を飛び越えて、独自に高頻度のカメラ更新やGPS要求を追加しない。

### 2.3 検索・DB
- **FTS5 は多くの実機で使えない**(`no such module: fts5`)。`places.search_text` 列の `LIKE` 検索を前提に実装する。FTS5 を新規に使うコードは `Fts5SupportDetector` を経由し、必ずフォールバックを用意する。
- 新しい列(`opening_hours` など)を使う場合、**列が無い旧DBで落ちない**こと(`PRAGMA table_info` で存在確認し null 扱い)。
- DB を開く処理は **UI スレッドで行わない**(`Dispatchers.IO`)。`SQLiteDatabase`/`rawQuery` 参照は 29 箇所あり、`close()` 漏れ(カーソルリーク)を確認する。`use { }` を徹底する。
- 行政界・キャッシュキーには**県名を含める**(BUG-80: 広島市中区/岡山市中区の衝突)。同名キーの衝突を新規キャッシュで再導入しない。
- 位置が変わらない/住所未判定の時に、毎秒全件スキャンしない(BUG-84)。**未判定でも位置キャッシュを更新する**。
- 表記ゆれ(ひらがな/カタカナ/ローマ字、全角/半角、長音、濁点)の**正規化関数は一つ**に集約し、DB生成側(`sandbox/data-tool`)と同一の規則を保つ。片方だけ変えると検索が当たらなくなる。

### 2.4 時刻・日時・営業時間
- `GpxParser` はミリ秒/タイムゾーン付きISO 8601で落ちた過去がある(BUG-81)。時刻パースは `java.time`(`Instant.parse`、`OffsetDateTime`)で統一し、失敗時に**現在時刻で上書きしない**(欠損として扱う)。
- 営業時間の判定は**端末のタイムゾーン**(`Asia/Tokyo` 固定にしない。ただし対象は日本)。日またぎ(例 `22:00-02:00`)、祝日、`24/7` を単体テストで確認する。判定不能なら**何も表示しない**(誤った「営業中」は害が大きい)。
- 日没によるテーマ切替(`DayNightManager`)は、オフラインで天文計算。緯度経度が未確定の時はデフォルト値(広島)を使い、**例外を出さない**。

### 2.5 並行処理・ライフサイクル
- `Dispatchers.` 参照 19 箇所、`LaunchedEffect`/`rememberCoroutineScope` 77 箇所。
  - `LaunchedEffect(key)` の key に不適切な値(毎回変わるオブジェクト)を渡すと、毎フレーム再起動する。
  - コールバックを保持する `DisposableEffect` では、`rememberUpdatedState` を使い**古いラムダを呼び続けない**(BUG-73)。
- `AndroidView(MapView)` は `onDetach`/`onDestroy` を呼ぶ(BUG-85)。MapLibre と osmdroid の両方で確認する。
- 非同期結果は**キャンセルと競合**を考慮する。連続入力(検索)は直前のジョブをキャンセルし、最新結果だけ表示する。
- `!!` 8 箇所、`catch (…Exception)` 28 箇所。`catch` で握りつぶすと原因が消える。最低限 `Log.w` で記録し、UI には出さない場合でも理由を残す。

### 2.6 オンライン補助(新規機能)
- ネットワーク呼び出しは必ず `OnlineFeatureGate` 経由。**3秒タイムアウト**、失敗はエラー表示せずオフライン表示に戻る。
- 取得データの**鮮度(取得時刻)を保存**し、古ければ表示しない(営業中などの期限付き情報)。
- 規約上、Google のサービス(タイル/Places/Directions/Street View/アイコン)を使わない。ライセンス表記(OSM・地理院・Overture・国土数値情報)は常時表示を維持。

## 3. UIの注意点

### 3.1 レイヤー順(Z-order)
- 地図スタイルのレイヤー追加順は、**道路 < ルート線 < 建物3D(または地面ドレープ) < ラベル < POI < 現在地**。
- 現状 `VectorMapView.kt` では `buildings-3d` の**下**にルート線を追加している(L743〜744)。3D 表示で建物に隠れる原因になり得る。X-Ray線(L761)で補っているが、3D建物がないズームでの見え方は別に確認する。
- スタイル JSON のレイヤーID(`buildings-3d`、`roads` など)を変更/リネームすると `addLayerBelow` が**無言で失敗**する(`getLayer(...) != null` の分岐に落ちる)。ID を変更するときは、全参照を `grep` し、`StyleLayerOrderTest` で固定する。
- ルート線は**ズームに応じて幅を補間**(`interpolate`)し、細すぎ/太すぎを避ける。

### 3.2 テーマ(ライト/ダーク)
- `Color(0x…)` の直書きが **232 箇所**。ダーク対応・一貫性の最大の障害。
  - 新規コードは `MaterialTheme.colorScheme` または `Theme.kt` のトークンのみ使う。直書き禁止。
  - 既存の直書き色は、タスクの範囲で触る時にトークンへ置換する(一括置換は影響が大きいので、画面単位で行う)。
- 地図スタイル(`protomaps_light/dark`)と UI のテーマ**同期**: 片方だけ切り替わる状態を作らない(地図が白いのに UI がダーク、など。過去の指摘)。

### 3.3 レイアウトと表示の安定
- 通知バナー・オンライン状態の表示で、**他要素を押し下げない**。オーバーレイ(`zIndex`、固定の予約領域)にする。過去に POI チップに被った不具合あり。
- オンライン⇄オフライン切替でボタン座標が動かないこと(`plans.md` の `LayoutStabilityTest`)。
- システムバー(edge-to-edge)の **WindowInsets** を必ず考慮。ジェスチャーナビ/3ボタンナビ両方、ノッチ/パンチホール、横画面。
- **画面常時点灯**はナビ中のみ。画面を抜けたら必ず解除(解除漏れは電池消耗)。
- フォント拡大(1.3x)・画面幅 360dp でテキストが切れない/重ならない。`Text("…")` 直書き 123 箇所は `strings.xml` へ移す(多言語・アクセシビリティ)。

### 3.4 タッチ・ジェスチャー
- 地図(MapLibre/osmdroid)上の Compose オーバーレイとの**タッチ競合**に注意。ボタンの外側タップが地図に抜ける/ボタンが地図を止める、の両方が起こり得る。ボタンは `clickable` + 最小タッチ領域 48dp。
- シート(ボトムシート)のドラッグと、地図のパン/ズーム/回転が干渉しないこと。シート展開中は地図ジェスチャーを無効にするか、領域を分離する。
- ズームの長押し連打(`GoogleZoomRepeatButton`)は、**離した時に確実に停止**する(`pointerInput` のキャンセル時にも)。

### 3.5 アニメーション・性能
- 60fps を維持。ナビ中の 1秒ごとの `mutableStateOf` 更新が、`MapScreen` 全体を再コンポーズさせていないか(Layout Inspector の recomposition count で確認)。大きな Composable は小さく分け、`remember` / `derivedStateOf` / `key` を使う。
- 地図のカメラ追従は **補間(ease)**。GPS 更新ごとのジャンプは酔いやすい。`CameraMotionPolicy` のしきい値を変える時は、実機で走行ログ再生(GPX)を使って確認する。
- 3D 建物+シャドウは GPU 負荷が高い。ズーム 14 未満では 3D を無効化する等の LOD を維持。

### 3.6 地図表示の落とし穴
- **タイル欠損域**はオフラインでは普通に起こる。透明/黒の穴ではなく背景色を出し、拡大時は低ズームタイルを引き伸ばす(オーバーズーム)。
- ラベルの**衝突**: 日本語は縦に長い名称が多い。`text-allow-overlap` を安易に true にしない。`symbol-sort-key` で優先度を付ける。
- POI アイコンは**高DPI**で崩れない(sprite の `@2x`)。ダークテーマ用の色違いを用意する。
- 帰属表示(OSM + 地理院)は、ボトムシートや HUD で**隠れない**位置に常時表示(P1 指摘済み)。

### 3.7 ナビ画面
- 距離表示の**丸め規則**: 〜1km は 10m 単位、1km〜は 0.1km 単位などを統一。案内の切り替わり時に「0m」「-5m」を出さない。
- 案内トリガ(500/200/50m)は**速度依存**にする(低速の自転車と、速い下り坂で同じ距離にしない)。同じ案内を**二重に読み上げない**(`VoiceGuidanceTrigger` のテストを維持)。
- 到着判定の半径は、屋内/高架・高精度でない GPS でも成立する値(20〜30m)にし、通過後に反転して再案内しない。
- ミュート/音声の `TextToSpeech` 初期化失敗時はサイレントに視覚案内のみで継続する。
