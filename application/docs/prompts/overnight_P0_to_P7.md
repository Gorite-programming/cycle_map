## 1. 絶対に守ること(違反したら即停止して記録)
1. **Git 操作の禁止**: `git add / commit / push / stash / reset / checkout / clean / rebase` をすべて実行しない。読み取り(`git status` / `git diff` / `git log`)は可。
2. **変更してよい場所は `re_test/` 配下のみ**。`application/`、`test/`、`AGENTS.md`、`build_*.py`、`scripts/`、`sandbox/` は**読み取りのみ**。
3. **削除・移動の禁止**(`re_test/` 内で自分が作ったファイルを除く)。`data/*.pbf`、`work/`、`venv/`、`local.properties`、keystore、`test/sample_img/`、`test/now.md` には触れない。
4. **`application/` の破壊的変更禁止**。`routing-core` / `osm-importer` は共有参照にする(複製しない)。共有元を書き換える必要が出たら、**書き換えずに**提案書 `re_test/proposals/<番号>_<題名>.md` に差分案を書く。
5. **`AGENTS.md` の編集は禁止**。「ZIP が 6 点になる」等の更新案は `re_test/proposals/agents_md_update.md` に書く。
6. **osmdroid は、代替が動くことをテストと(可能なら)実機で確認するまで削除しない**。
7. Google のタイル・アイコン・ロゴ・スクリーンショットを使わない。
8. ネットワーク必須の機能を追加しない(`plans.md` §2)。
9. **偽の合格を作らない**: 実行していないテストを「成功」と書かない。実機で確認できなかった項目は「未確認(実機)」と書く。採点は**控えめ**に付け、根拠のない加点をしない。
10. 破壊的操作・不可逆な操作・秘密情報の扱いが必要になったら**実行せず**、記録して別のタスクへ進む。

## 2. 進め方

### 2.1 進捗ログ(最重要。朝に人間が最初に読む)
`re_test/NIGHT_LOG.md` を作り、**各タスクの開始・完了・失敗のたびに追記**する(追記のみ。過去の記録を書き換えない)。1 エントリの書式:

```
## [HH:MM] <フェーズ-タスク> <状態: 開始/完了/失敗/保留/スキップ>
- 変更: <ファイル一覧>
- テスト: <コマンド> → <件数/合否>(未実行なら「未実行」と理由)
- 実機: <確認済み/未確認(理由)>
- メモ: <判断・リスク・保留理由>
```

### 2.2 フェーズの順序
`P0 → P1 → P2 → P3(P3-0 から) → P4 → P5 → P6 → P7`。各フェーズの仕様は `plans.md` §3〜§8。P3-0(フォント/アイコンのオフライン化)は P3 の最初に必ず行う。

### 2.3 各タスクの完了条件(ゲート)
各タスクの完了ごとに、次を**すべて**満たすこと。満たせなければ次のタスクへ進まない(§2.4 に従う)。
1. `cd re_test && ./gradlew :routing-core:test :osm-importer:test :app:testDebugUnitTest` が**全件成功**。
2. 新しい振る舞いには**新しいテスト**を足す(`plans.md` §8 の必須テストを含む)。
3. `:app:assembleDebug` が成功する(ビルド環境は `AGENTS.md` に従う)。
4. `parity_checklist.md` の該当行を更新(証跡のパスかテスト名を書く)。実機で未確認なら 🟡 にして理由を書く。
5. `plans.md` §9 の自己採点表に、該当項目の「実績」と根拠を書く(控えめに)。
6. `NIGHT_LOG.md` に完了を追記。

### 2.4 詰まったとき(質問で止まらない)
- 同じエラーを **3 回**直そうとして直らなければ、そのタスクを「保留」にして `NIGHT_LOG.md` に原因・試したこと・次の案を書き、**依存しない別タスクへ進む**。
- 保留のタスクに依存するタスクは「スキップ(依存)」と記録して飛ばす。
- 仕様の曖昧さは、**`overhaul_plan.md` → `plans.md` → `cautions.md` の優先順**で解釈する。それでも決められない場合は、**元の `test/` の挙動を維持する側**を選び、判断を `NIGHT_LOG.md` に残す。
- **ビルドが壊れた状態で次へ進まない**。直せない場合は、そのタスクの変更を**自分で元に戻す**(Git は使えないので、自分が編集した箇所を手作業で戻す。戻せない大規模変更は新規ファイルにとどめ、既存ファイルへの接続を外す)。

### 2.5 実機検証
- `adb devices` で Galaxy S21 が見えていれば、機内モード(オフライン)と Wi-Fi(オンライン)の**両方**で `plans.md` の確認を行い、スクリーンショットを `re_test/screenshots/<task-id>_{offline,online}.png` に保存する。
- 端末が見えない場合は、実機項目をすべて「未確認(実機)」とし、**他の作業を止めない**。ユニットテスト、スクリーンショットテスト、スタイル JSON の静的検証で代替できる範囲だけ代替し、それ以上は主張しない。
- 端末のアプリデータや設定を消す操作(`adb uninstall`、`pm clear`、`rm` など)は**禁止**。`adb install -r` は可(署名鍵が違って失敗した場合は記録して実機検証を諦める)。

### 2.6 リソース・時間
- 長時間のコマンドはバックグラウンドで実行し、完了を待つ(ポーリングのループはしない)。
- 重いビルドを同時に複数走らせない。Gradle のメモリ設定は `AGENTS.md` と既存設定に従う。
- 一つのタスクで試行は 3 回まで。

## 3. 最終段階(P7)の完了処理
全フェーズが終わった(または進められなくなった)ら、次を作成して**停止**する。
1. `re_test/FINAL_REPORT.md`:
   - フェーズごとの結果(完了/保留/スキップ)
   - `plans.md` §1 の式に従った**互換度の再計算**(F% / B% / 全体%)。根拠のない項目は 0 とみなす
   - テスト結果(件数・合否)、実機の確認済み/未確認の一覧
   - 保留タスクの一覧と原因、人間の判断が必要な事項
   - オフライン/オンラインの表示差の確認結果(`plans.md` §2.2 の各行を ✓ / ✗ / 未確認)
   - 提案書(`re_test/proposals/`)の一覧
   - **コミットすべき変更のまとめ**(`git status` と `git diff --stat` の出力、フェーズ単位の推奨コミット分割案)
2. `parity_checklist.md` と `plans.md` §9 の最終更新。
3. 以降は何もしない(Git 操作もしない)。
