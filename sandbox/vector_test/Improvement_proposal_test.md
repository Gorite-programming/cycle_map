# vector_test 論理的懸念点と改善提案

`cyclemap/sandbox/vector_test/` 内のファイル（特に `MainActivity.kt`）を精査した結果、UI/UXおよびパフォーマンス、堅牢性の観点から以下の論理的な懸念点（ロジック上のバグ・ボトルネックの種）が発見されました。これらに対する改善案をリスト化します。

## 1. 3D/2Dレイヤー切替のチャタリング (Hysteresisの欠如)
* **懸念点**: `MainActivity.kt` にて、チルト角 `pos.tilt > 15.0` の単一しきい値で3Dレイヤー（`buildings-3d`）と2Dレイヤー（`buildings-2d`）の表示を切り替えています。ユーザーの指の微細なブレによりカメラが15度付近で揺れた場合、レイヤーの表示・非表示が高速で切り替わり（チャタリング）、画面のちらつきや深刻な描画スパイクが発生する恐れがあります。
* **改善案**: 制御工学的な「シュミットトリガ（ヒステリシス）」を導入し、「チルト角が16度を超えたら3Dをオン、14度を下回ったら2D（3Dオフ）に戻す」のように、しきい値にバッファ（マージン）を持たせるロジックへ変更してください。

## 2. メインスレッドでのファイルI/O (Asset Read)
* **懸念点**: `applyMapStyle` メソッド内で、JSONスタイルシートの読み込み（`context.assets.open(...).bufferedReader().use { it.readText() }`）を同期的に実行しています。スタイルファイルは大きく、特に `MapLibre` のスタイル解析は重いため、メインUIスレッドをブロックし、アプリ起動時やスタイル切替時にUIの「ジャンク（カクつき）」やフリーズを引き起こします。
* **改善案**: Kotlin Coroutines の `Dispatchers.IO` を用いて、別スレッドでJSONファイルを読み込み・文字列置換を行った上で、メインスレッドに戻して `map.setStyle` を呼び出す非同期処理（`suspend fun`）へリファクタリングしてください。

## 3. 過剰な先読み（Prefetch）によるメモリ逼迫リスク
* **懸念点**: `map.prefetchZoomDelta = 4` の設定は、現在の表示ズームレベルより4段階も深い高解像度タイルを事前にキャッシュすることを意味します。ベクターデータは高ズームになるほど頂点データが爆発的に増加するため、Android端末やSBC（Edge 2など）の限られたメモリ環境において、この設定はOOM（Out Of Memory）クラッシュを引き起こす極めて高いリスクがあります。
* **改善案**: `prefetchZoomDelta` の値をベクタータイルに適した `1` または `2` 程度に引き下げるか、システムメモリの空き容量に応じて動的に調整する制御を入れてください。

## 4. ハードコードされた領域外ジャンプのリスク
* **懸念点**: 画面右下のクイックアクション（平和公園、広島駅、宮島）の座標がハードコードされています。将来的に他県（例: 山口県）のPMTilesデータを読み込んだ状態でこれらのボタンを押すと、タイルデータが存在しない領域へカメラがジャンプしてしまい、画面が真っ白（復帰困難）になる論理的欠陥を抱えています。
* **改善案**: 読み込んだPMTilesのメタデータ（`bounds`）を取得し、ターゲット座標がそのバウンディングボックス内に含まれている場合のみボタンを有効化するか、読み込まれているデータの中心（Center）へジャンプする動的ボタンへ改修すべきです。

## 5. オフラインフォールバックの矛盾
* **懸念点**: `PMTiles` ファイルが存在しない場合のフォールバック先として、オンラインのURL（`https://build.protomaps.com/...` 等）を指定しています。これは開発中は便利ですが、「完全オフライン」という最終要件と矛盾しており、実際の機内モード等での検証時に通信エラーによる例外クラッシュ（または無限ロード）を誘発します。
* **改善案**: ファイルが見つからない場合はオンラインへフォールバックするのではなく、MapLibre の初期化を中止し、「オフラインデータが存在しません」という警告UIを表示する「完全隔離・フェイルセーフ」ロジックへ移行すべきです。

* ETA算出のチャタリング防止（EMA/速度ホールド）
* 楕円体大圏距離計算（測地線距離）の導入
* ハッシュインデックスのダブルハッシュ化
